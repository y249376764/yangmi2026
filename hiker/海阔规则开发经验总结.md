# 海阔规则开发经验总结（蜘蛛加速器 v1 正式版）

> 这份文档是从 v5 到 v1 共 40 多版迭代里，用真实报错换来的。
> **以后写任何海阔规则 / 源，都要照「发布规范」那一节执行。**

---

## 一、最高频的坑：回调作用域（栽了 11 次）

### 现象
页面能渲染，一点按钮就报 `ReferenceError: xxx 未定义`。
踩过的名字：`readJk` `res` `isAudioFile` `_fetchFast` `_toApiSite` `nm` `gn` `phLoad` `PH_CANDS` `DEFAULT_DIRS` `tags`

### 原因
`lazyRule` / `$.toString` / `confirm` / `input` 的回调会被海阔**单独 eval**，
**拿不到页面顶层的变量和函数**。

### 规则
> **回调内部必须完全自包含：不调用页面函数，不读页面顶层变量。**

所有依赖的数据用两种方式带进去：

```js
// ✅ 方式 1：$.toString(fn, 参数) —— 参数会被序列化进去
$("hiker://empty#noHistory#").lazyRule(function (p, vid) {
    putMyVar("acc_py", p);
    return "hiker://page/pydetail#fullTheme#";
}, pyPath, vodId)

// ✅ 方式 2：MyVar / storage0 —— 最稳
putMyVar("acc_kw", kw);
$.toString(function () {
    var k = getMyVar("acc_kw", "") || "";
})
```

### 跨层陷阱（v31 的 `tags` 未定义）
两级 `$.toString` 嵌套时，**第二层不能引用第一层的形参**：

```js
lazyRule(function (names, paths, tags) {        // 第一层形参
    showSelectOptions({
        js: $.toString(function (ps, tg) {...}, names, tags)  // ❌ tags 是外层形参
    })
}, siteNames, sitePaths, siteTags)
```

**改成 MyVar 传递，别传参。**

## 三、结构性设计坑

### 1. `MY_PAGE` 串页（v28→v29）
同页混两种模式，上滑翻页后 `MY_PAGE` 递增，
把包在 `if (isP1)` 里的导航/切换按钮全弄没了。

**解法**：模式切换时记偏移量：
```js
putMyVar("acc_reset", "1");
// 下次执行
if (needReset == "1") { pgoff = MYPG - 1; }
var pg = MYPG - pgoff;
```

### 2. 搜索卡住（v46）
只有占位符没写执行代码 → 永远"搜源中"。
串行逐个跑 → 一个站卡 20 秒，后面全堵死。

**解法**：默认只搜当前站点 + `be()` 并发（全部站点模式）。

### 3. 结果倒序（v49）
每批都 `addItemAfter("acc_skel", data)` → 后到的插到最前面。

**解法**：维护游标追加到列表末尾：
```js
var prev = getMyVar("acc_blast", "acc_skel");
addItemAfter(prev, data);
putMyVar("acc_blast", tail);
```

### 4. CDN 挂掉（v47 收不到更新）
`cdn.jsdelivr.net` 曾实测 502/403。

**解法**：**所有远程请求必须三源兜底**：
```
cdn.jsdelivr.net → fastly.jsdelivr.net → raw.githubusercontent.com
```

### 5. 回退策略
v19 之后为了加功能重写了加载逻辑，把已验证的代码丢了，连续几版坏掉。

> **在能用的基线上做增量，不要在坏掉的基础上打补丁。**

## 四、发布规范（以后每个规则 / 源都要有）

### 1. 公告按钮（必须有）
放在 icon_5 导航里，文案和网址**从远程拉**，不写死。

⚠️ **`$(数组, 类型).select(回调)` 必须 `return`**（聚影 `SrcJuying.js` 全文都是
`return $(menubtns,2,"标题").select(...)`）。
v1 把它当语句调用、结果丢弃 → **点公告完全没有反应**。

```js
d.push({
    title: "公告",
    pic_url: ICONS["zz_notice.svg"],
    col_type: "icon_5",
    url: $("hiker://empty#noHistory#").lazyRule(function () {
        var _n = "", _u = "";
        try { _n = getMyVar("acc_notice", "") || ""; } catch (e) { }
        try { _u = getMyVar("acc_notice_url", "") || ""; } catch (e2) { }
        if (!_n) { _n = "本规则由作者免费分享 · 禁止任何形式售卖"; }
        if (!_u) { _u = "https://navpage-2026.surge.sh/"; }
        try { putMyVar("acc_nurl", _u); } catch (e0) { }
        // ★ 必须 return；标题栏显示正文；不要在 select 回调里再套 confirm（嵌套弹窗会失效）
        return $(["📋 复制网址", "🌐 打开网址"], 1, "📢 " + _n).select($.toString(function () {
            var _nu = "";
            try { _nu = getMyVar("acc_nurl", "") || ""; } catch (g) { }
            if (!_nu) { _nu = "https://navpage-2026.surge.sh/"; }
            if (MY_INDEX === 0) {
                try { setClipboard(_nu); return "toast://已复制：" + _nu; } catch (g3) { }
                return "copy://" + _nu;      // setClipboard 不可用时降级
            }
            return _nu;
        }));
    })
});
```

- **不要用 `alert()`** —— 不是海阔标准 API，聚影源码里也没有
- **不要嵌套弹窗**：`select` 回调里再调 `confirm` 大概率不生效

### 2. 自动更新检查（必须有）
每天首次打开查一次 `version.json`（三源兜底），有新版弹窗，
点确定 `fetch(version.json.url)` 自动导入。

### 3. 远程开关 status.json（必须有）
```json
{
  "enabled": true,
  "min_version": 50,      // ← 用 BUILD 纪元比较，不是 MY_RULE.version
  "msg": "",
  "notice": "本规则由作者免费分享 · 禁止任何形式售卖",
  "notice_url": "https://navpage-2026.surge.sh/"
}
```

#### ⚠️ 版本号重置会导致旧版永不淘汰（v1~v2 收不到更新提示的真因）
版本号从 49 重置成 1 之后：
- `version.json.v = 2`，用户手上是 v49 → `2 > 49` 为假 → **永不提示更新**
- `min_version = 2`，v49 的 `49 >= 2` → **也不停用**
- 结果：**v49 完全无感，既收不到提示也不会被淘汰**

#### ✅ 解法：BUILD 纪元常量（与显示版本号解耦）
规则内置一个**只增不减**的常量，停用判断用它而不是 `MY_RULE.version`：

```js
var BUILD = 50;   // 正式版从 50 起；以后每发一版 +1

if (_mv > 0 && BUILD < _mv) {   // _mv = status.json.min_version
    _allowed = false;           // 停用，强制更新
}
```

| 版本 | 内置 BUILD | min_version=50 | 结果 |
|---|---|---|---|
| v49 / v1 / v2 | 无（视为 0） | 0 < 50 | **停用，显示「立即更新」** |
| v3 | 50 | 50 < 50 假 | **放行** |
| 以后 v4（BUILD=51，min=51） | 51 | v3: 50<51 | **v3 停用** |

**发新版流程**：规则 `version` +1 → 规则 `BUILD` +1 → `status.json.min_version` 设为新 BUILD
→ `version.json.v` 设为新版本号 → 上传。

#### ⚠️ 更新提示不能「每天只查一次」
v2 用 `if (上次日期 !== 今天)` 判断：
**当天已经查过一次（那时还没有新版），当天发布的新版永远提示不到。**

改成**时间戳节流（2 小时）+ 已提示版本去重**：
```js
var _lastMs = parseInt(getItem("acc_vchk_ms", "0")) || 0;
if (nowMs - _lastMs > 7200000) {          // 2 小时
    请求 version.json（三源兜底）
    setItem("acc_vchk_ms", String(nowMs));
    var _shown = getItem("acc_vshown", "") || "";
    if (remote > local && _shown !== String(remote)) {
        confirm(...)   // 确定/取消都记 acc_vshown = remote，同一版本不再重复打扰
    }
}
```

### 4. 作者模式
管理菜单加「🔧 作者模式」，本地标记 `acc_owner=1`，
**跳过停用检查和版本拦截**，防止误伤自己。

## 五、发布前的固定检查项

```bash
node --check 每一页           # 语法
check_all.py      acc_vN.json # 回调作用域
check_tostring.py acc_vN.json # 形参/传参、跨层引用
check_html.py     acc_vN.json # 富文本前缀
check_input.py    acc_vN.json # input 回调取值
```

**四个检查器都是从真实报错里长出来的，不是摆设。**
v30 的 `tags` 未定义、v34 的乱码、v35 的 input 误用，
都是检查器精确抓出来的。

## 六、必须承认的边界

- 公开仓库 **防不住爬虫**，只能做到「随时废掉」。
- 停用开关是"明"的，**懂行的人能改 hosts 绕过**，拦得住普通传播。
- 断网时远程检查放行（否则会误伤自己）—— 这也意味着断网能绕过开关。
- Python 蜘蛛本身慢的话，规则层加不了超时（PythonHiker 不支持中断），只能换站。
