## 零、发布规范（写任何规则或源都要遵守）

1. **必须带「公告」按钮** —— 文案从远程 `status.json.notice` 拉取，不放本地写死
2. **必须带更新检查** —— 远程 `version.json`，有新版本弹窗提示
3. **必须带远程开关** —— `status.json.enabled` 总闸 + `min_version` 淘汰旧版
4. **外链只复制不打开** —— App 内直接打开第三方网址会失败退回起始页
5. **版本号与 BUILD 分离** —— 版本号给人看，BUILD 只增不减，用于淘汰判定
6. **规则顶层禁止 `return`** —— 见第十五节，会直接崩溃
7. **每个新功能都要配远程开关** —— 万一线上异常能远程关掉，不必发新版

## 一、回调作用域（栽过 11 次，最高频）

### 现象
`ReferenceError: "xxx" 未定义`，行数指向回调内部。

### 根因
`lazyRule` / `$.toString` 的回调是**独立 eval**，拿不到页面顶层变量。

```js
var DEFAULT_DIRS = [...];                    // 顶层
$.toString(function () {
    return DEFAULT_DIRS;                     // ❌ undefined
});
```

### 规则
- 回调里**只能用**：形参、`MyVar`（`getMyVar`/`putMyVar`）、全局内置（`input`、`MY_INDEX`、`MY_PAGE`）
- 数据一律走 `putMyVar` → 回调里 `getMyVar`
- **两级 `$.toString` 更不能传参**：第二层引用第一层形参必炸

### 自动化
`check_all.py` 扫描所有回调体里引用的顶层 var/function，违规即报错。

---

## 二、回调形参与传参

### 海阔 `input` 回调：输入值在**全局 `input`**，形参是额外参数

```js
// ✅ 聚影 SrcJyMenu.js:237
$(默认, "提示").input((额外参) => {
    val = parseInt(input);      // ← 输入值在全局 input
}, 额外参值);

// ❌ 错误：把形参当输入值
.input(function (v) { var nv = String(v); })
```

### `lazyRule` 形参个数必须与末尾传参一致

```js
.lazyRule(function (a, b) {...}, v1, v2)     // ✅ 2 对 2
.lazyRule(function (a) {...}, v1, v2)        // ❌ 会被检查器抓出
```

自动化：`check_tostring.py`、`check_input.py`

## 三、`select()` 不能被 `lazyRule` 包一层

### 现象
点按钮**完全没反应**，连弹窗都不弹。

### 根因
```js
url: $("hiker://empty#noHistory#").lazyRule(function () {
    return $([...], 1, "标题").select(...);   // ❌ 两层嵌套
});
```
海阔只执行外层 `lazyRule`，**内层 select 不会被触发**。

### 正确写法（聚影 `SrcJuying.js` 同款）
```js
url: $(["📋 复制网址"], 1, _noticeBig).select($.toString(function () {
    var _w = getMyVar("acc_nurl", "");
    return "copy://" + _w;
}));
```

### 口诀
- ❌ `lazyRule` 内 `return $().select()`
- ✅ `select` 回调内 `return $().lazyRule()`（这个方向安全）

### 配套
select 回调是独立 eval → **页面顶层就要 `putMyVar()`**，别指望回调读顶层变量。

## 四、富文本标记（乱码真因）

海阔 title/desc 里的内联 HTML **必须加 4 个特殊引号前缀**才会渲染：

```
单引号版：''''    (U+2018 U+2018 U+2019 U+2019)
双引号版：““””    (U+201C U+201C U+201D U+201D)
```

聚影每一处都这么写：
```js
title: '‘‘’’<strong><font color="' + Color + '">' + it + '</font></strong>'
desc: "站源：" + sname + "  ““””<small><font color=grey>(...)</font></small>"
```

**少了前缀 → 标签原样打出来**，用户看到 `<strong><font color="#09c11b">蓝光 >`。

自动化：`check_html.py`（识别字面量 / PRE 变量 / `\u` 转义三种形式）

## 六、翻页（`MY_PAGE` 是海阔内置，规则改不了它）

## 七、并发搜索 `be()`（聚影 `SrcJuying.js:172`）

```js
let list = ssdatalist.map(item => ({
    func: task,                                 // ← 每项自带 func
    param: { data: item, name: name },          // ← 参数对象，不是字符串
    id: item.url
}));
be(list, { func: function (obj, id, error, taskResult) {
    if (taskResult.success == 1) { addItemBefore(id, taskResult.result); }
}});
```

**易错点**
- `param` 传字符串 → 回调里得到 `[object Object]`
- 结果从 `taskResult.result` 取，不是 `obj`
- 回调体里不要引用页面顶层变量（作用域坑）
- `be()` 不可用 → 降级串行前 8 站 + 时间预算

### 搜索性能
- **默认只搜当前站点**（豆瓣走 suggest API，秒出，不启动 Python）
- 「全部站点」才 `be()` 并发 20 站
- 结果字段容错链：`list` → `data.list` → `data` → 数组本身

## 八、远程配置与更新机制

### 多源兜底 **绝不能先成功就 break**

```js
// ❌ 致命：cdn 返回旧版缓存（HTTP 200 但内容陈旧）→ break → 永远读到旧值
for (...) { request(url); if (ok) { use; break; } }

// ✅ 全部试一遍，数值取最大（新鲜的自然更大）
["min_version","build","v"].forEach(k => {
    if ((+jo[k]||0) > (+out[k]||0)) out[k] = jo[k];
});
```

**源顺序**：`raw.githubusercontent.com` 优先，jsDelivr 垫底（间歇性 502 + 陈旧缓存）。
**更新包强制走 raw**，否则可能 CDN 缓存旧包，更新完反而降级。

### BUILD 纪元常量（版本号归 1 的救星）
```js
var BUILD = 56;                        // 只增不减
if (mv > 0 && BUILD < mv) 停用;        // 不用 MY_RULE.version 比较
```
版本号给人看（可重置），BUILD 用于淘汰。**两套独立**。

### 强制更新无退路
海阔 `confirm` 无法真正隐藏取消按钮 → **让 cancel 执行同样动作**（也 fetch 更新）。
不记 `vshown`，否则给了永久退路。

### 离线兜底
远程全挂时用内置 `FLOOR` 判定，避免 CDN 陈旧缓存让旧版永远不被淘汰。

## 九、性能优化

### 首页扫描做文件缓存
`accScan()` 用 `java.io.File` 遍历，每次打开都跑 → 慢 + 反复触发「动态加载 Java 代码」授权弹窗。
结果写 `hiker://files/zz_scan.json`，TTL 10 分钟；命中时零 Java 调用。
**「重新扫描」必须先 `deleteFile` 清缓存再 refreshPage**。

### PythonHiker 懒加载
首页顶部无条件 `$.require(PythonHiker.js)` 只为判断按钮文案 → 改成只 `fileExist()`，真正 require 留到按钮回调。

### 远程列表本地缓存
影视3 的 115KB 站点列表：第 1 页下载一次写文件，翻页读本地。否则每页重下必超时。

## 十二、工具链注意事项

- Python 脚本里不要写 `"\uD83D\uDCCB"` 这类 **lone surrogate 字面量**，会触发
  `UnicodeEncodeError: surrogates not allowed`。**直接写真实 emoji 字符**。
- 每行替换走完整字符串匹配，**不要按行号截断**（曾把一行代码切成半个字符串）。
- 在**能用的基线上做增量**，别在坏掉的版本上继续打补丁。
- 同一份代码里两种写法并存时，错的那个一眼可见 —— 横向对比是最快的定位方式。
- 沙盒偶尔报 `Stale file handle`：写大文件后 `flush()` + `os.fsync()`，报错就删掉重写。

## 十五、规则顶层禁止 `return`（v10 崩溃修复）

### 报错
```
解析失败！JS编译出错：返回的值无效 (JSEngine#1246)
```

### 真因
我在首页规则**文件末尾**写了：

```js
// 文件最末尾（顶层）
try {
    if (首次进入) {
        return $(["📋 复制网址"], 1, _noticeBig).select(...);   // ❌
    }
} catch (e) { }
```

**查聚影 `SrcJuying.js` 全文 1618 行：`grep '^return '` 结果为 0** ——
所有 `return` 都在 `lazyRule` / `confirm` / 函数体内部，**没有一处顶层 return**。

顶层 `return` 出去的 `select()` 对象对海阔是**非法返回值** → 直接崩。

### 为什么 `node --check` 没抓出来
Node 把 `.js` 当 CommonJS 模块解析，而 CJS 本身就被包在函数里，**顶层 return 合法**。
海阔却是按脚本/eval 语义执行 → 非法。

**教训：`node --check` 通过 ≠ 海阔能跑。** 顶层控制流要单独人工检查。

### 正确做法：用「脚本完成值」代替 return

```js
// 文件最末尾（setResult 已执行完）
var _popupUrl = "";
try {
    if (首次进入) {
        setItem("acc_notice_shown", 指纹);
        _popupUrl = "confirm://" + 公告全文 + ".js:'copy://" + 网址 + "'";
    }
} catch (e) { }

if (_popupUrl) {
    _popupUrl;      // ← 最后一条语句的「值」= 完成值
}
```

- 需要弹窗：完成值 = URL 字符串（`confirm://` 是官方协议，海阔会执行）
- 不需要：`if` 无 `else` → 完成值 `undefined`，海阔沿用 `setResult` 已渲染的结果

**没有 `return` 关键字，且不会覆盖已渲染的页面。**

### `confirm://` 协议格式
```
confirm://提示信息.js:'动作url'
```
点【确定】执行动作 url，点【取消】只关闭。
例：`confirm://公告全文.js:'copy://https://xxx'`

### 配套：远程 kill-switch
新功能（尤其弹窗这类交互）一律配远程开关，`status.json` 加 `popup: false` 即可一键关闭，
**不用发新版**：

```js
// accRemote 内：任一源说关就关
if (out.popup !== false && jo.popup === false) { out.popup = false; }
```

## 十三、复制功能必须用 `copy://`（v9 修复）

用户反馈"前面能复制，现在复制失败"。真因：

```js
try { setClipboard(text); return "toast://已复制"; } catch (e) { }
return "copy://" + text;      // ← 永远走不到
```

`setClipboard()` / `setClip()` 在海阔里**可能静默失败**（函数存在、不抛异常、但不写入剪贴板），
代码却已经 `return toast` 了 —— 用户看到"已复制"，实际剪贴板没变。

**正确做法**：只用 `return "copy://" + text;`，不要让任何包装函数抢在前面。

全库已清理：首页复制最新版链接、zsite 复制路径、公告复制网址，统一 `copy://`。

## 十四、公告弹窗的正确形态（v9）

要求：公告大一点、内容直接可见、底部只留一个复制网址按钮、首次进入自动弹。

### 形态

```
📢 免费分享 · 禁止售卖
━━━━━━━━━━━━━━
更多资源请访问：
https://navpage-2026.surge.sh/
━━━━━━━━━━━━━━
本规则免费分享，禁止任何形式售卖

        [ 📋 复制网址 ]
```

内容放在 **select 的第三个参数（标题）**，多行用 `\n`。
**不要**做"复制公告全文"按钮 —— 看得见就不用复制。

### 首次自动弹窗（关键技巧）

弹窗代码放在**文件末尾**，即所有分支的 `setResult()` 都执行完之后：

```js
// 各分支已 setResult(d) 渲染完页面
// ...文件末尾：
if (需要弹) {
    return $(["📋 复制网址"], 1, _noticeBig).select(...);
}
```

这样海阔**先渲染页面、再弹窗**。万一弹窗机制不生效，首页照常显示，不会白屏。

若把弹窗放在规则开头 `return`，页面还没渲染 —— 用户点遮罩关掉弹窗就是空白页。

### 指纹控制重弹

```js
var _nk = String(_notice.length) + "_" + String(_noticeUrl).slice(-12);
if (_ns !== _nk) { setItem("acc_notice_shown", _nk); 弹窗; }
```

远程公告内容一变 → 指纹变 → 重新弹一次；内容不变则只弹一次，不骚扰。

## 十六、`be()` 回调同样是独立 eval（v11，第 12 次栽同一个坑）

### 现象
「😕 未找到 · 耗时 0.4s · 扫了 398 个站点」—— 0.4 秒扫完 398 站，必然是全部瞬间失败。

### 真因
zplay 页旧的 be 回调里用了页面顶层变量：

```js
be(taskList, {
    func: function (obj, id, error, tr) {
        if (java.lang.System.currentTimeMillis() - t0 > LIMIT_MS) { return "break"; }  // ❌ t0 是顶层
        if (tr.success == 1) { ... mkRow(...) ... got++ ... okCount++ }                 // ❌ 全是顶层
    }
});
```

回调拿不到 `t0` → 一进来就抛异常 → 被 `catch(ex){}` **静默吞掉** → 所有结果丢弃、计数为 0。
**耗时 0.4s 是因为异常抛得比搜索还快。**

### 修法
1. 计数全部走 `MyVar`（`acc_zp_got` / `acc_zp_ok` / `acc_zp_t0` / `acc_zp_last`）
2. **item 在 task 内部自包含构造**，不引用页面的 `mkRow`
3. 并发站点数限制（398 个全开会拖垮线程池）
4. 失败时显示诊断，别只写一句「未找到」

### 检查器漏洞（关键）
旧 `check_all.py` 只扫 `.lazyRule(` / `.select(` / `.confirm(` / `.input(` 后的回调，
**`be(list, { func: function(){} })` 完全没覆盖** —— 所以这个 bug 一直没被发现。

已增强三点：
- 回调模式加入 `func:\s*function`
- 顶层变量收集改为**任意缩进**（海阔页面里变量常定义在 `try{}` 块内，旧版只认 `^var`）
- 匹配前剥离字符串字面量与注释，并用 `(?<![\w$.])` 排除 `cc.s` 这类属性名误报

**增强后立刻在 v10 上抓出 zplay 的 4 个违规。**

## 十七、`confirm://` 里绝不能有换行（v11）

### 现象
公告弹窗只显示「免费分享·禁止售卖...」，「更多资源：网址」看不见，点确定也没复制。

### 真因
`confirm://` 是 **URL 协议**，文本里的 `\n` 会直接把协议串截断：

```js
"confirm://" + "📢 免费分享\n更多资源：https://xxx\n" + ".js:'copy://" + url + "'"
//                ↑ 第一个 \n 之后的全部内容（含 .js:'copy://...'）都被吃掉
```

结果：只显示第一行，且尾部动作丢失 → 点确定无反应。

### 修法
公告文本一律**单行**，用 `｜` 分隔，末尾再 `replace(/\n/g, " ")` 兜底：

```js
var _noticeBig = "📢 免费分享 · 禁止售卖";
_noticeBig += "｜更多资源: " + _noticeUrl;
_noticeBig += "｜点【确定】即复制网址";
_noticeBig = String(_noticeBig).replace(/\n/g, " ").replace(/\r/g, " ");
```

**并让网址直接出现在正文里** —— 即使复制不生效，用户也能肉眼看到、手动记下。

### 通用原则
任何塞进 URL 协议的文本（`toast://` / `copy://` / `confirm://` / `hiker://`）
都要先去掉换行，否则后半段静默丢失。

## 十八、不要给弹窗塞动作（v12，公告连坏 4 版的总结）

### 时间线
| 版本 | 做法 | 结果 |
|---|---|---|
| v8 | 顶部文本 + 图标按钮复制 | 能用 |
| v9 | 改弹窗 + `setClipboard()` | 静默失败，提示"已复制"实际没复制 |
| v10 | 改 `copy://` 协议 | 弹窗只显示半截，点确定无反应 |
| v11 | 查出真因：`confirm://` 里的 `\n` 截断协议 | 仍然只显示半截 |
| **v12** | **回退：不要复制按钮，不要弹窗动作** | 稳定 |

### 教训
**弹窗/URL 协议只能承载「展示」，不要承载「动作」。**

- `confirm://提示.js:'动作url'` —— 提示里任何 `\n`、引号、`#` 都会截断协议，动作静默丢失
- 复制类动作在弹窗里尤其脆弱：`setClipboard()` 静默失败、`copy://` 受协议截断影响

### 正确做法（v12 采纳）
1. **公告做成页面顶部的常驻 `text_1`**，网址直接写进 `desc`
2. 需要复制时**靠海阔自带的长按复制菜单**，比自己实现可靠得多
3. 图标按钮的弹窗**只展示**，回调 `return "hiker://empty"`

### 通用原则
> 能用「页面元素 + 系统自带交互」解决的，不要用「弹窗 + 自定义动作」。

## 十九、加载失败要能自愈，不能把用户困在报错页（v12）

### 现象
首页蜘蛛模式报错「找不到函数 runPy」，只有「重试」按钮 —— 用户点重试还是同样的错，出不去。

### 根因链
1. 影视3 下载站点时**只校验长度**（>100 字符就写入）
2. 远程返回 HTML 错误页（远超 100 字符）被当成源码写入 `.py`
3. 之后 `runPy` 这个坏文件 → 抛异常 → 首页显示「加载失败」
4. 用户只能重试，**永远出不来**

### 修法（三层）
1. **下载时校验内容**：拒绝 HTML（`<!DOCTYPE` / `<html`）、必须含 `def `
2. **报错页给「🍿 回到豆瓣」按钮**
3. **同一站点连续失败 2 次自动回豆瓣**（记 `acc_failc` / `acc_failp`）

### 通用原则
> 任何可能失败的入口，都要留一条「回到已知可用状态」的路。
> 「重试」不是出路，重试只会重复同样的失败。
