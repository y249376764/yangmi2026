# 经验：选映分享修复 —— 复用同包已有实现

日期：2026-11-02 · 版本：星集Media 2026110228

## 现象

- 星集「规则管理」的分享正常，生成短口令：`云口令：星集规则￥<密文>￥[漫]MiFun动漫(2)(云6)@import=js:…`
- 选映界面的分享不可用：云剪贴板一个都传不上去，最后只剩几十 KB 的自包含长口令。

## 根因：同一个包里有第二套实现

| 入口 | 调用 |
|---|---|
| 规则列表 / 解析列表 / 批量分享 | `qdShare('rule', shareArr)` |
| 选映界面 | `qdShareCloudAuto(key)` → `qdShareCloud('rule', _it)` |

`qdShare` 会弹「选择分享方式」（云剪贴板1…N + 云口令文件），上传后拼短口令；
`qdShareCloud` 没有弹窗、只试云剪贴板、异常全部 `catch{}` 吞掉。

不是云剪贴板坏了，是选映走了另一套代码。

## 修法

选映入口接回那一套，只搬调用：

```js
// 菠菜源
return qdShare('bocai', [{ key, name, api, detail, enabled }]);
// 规则源
return qdShare('rule', [_it]);
```

`qdShareCloudAuto` 只保留「按 key 找到源、读出代码」，找到后交给 `qdShare`，参数结构与 `ruleList.js`、`parse.js` 一致。

## 方法论

同一个包里已有能跑的同类功能时，第一动作是**找它怎么调的，把调用搬过去**，不是按原理重写。

1. 定位同类入口：搜函数名、搜界面文案、看别的页面怎么调；
2. 对齐三样：同一份数据、同一个函数、同样的参数结构；
3. 只搬调用，不新增 wrapper、不新建分支 —— wrapper 正是元宝这版坏掉的原因；
4. 只有「抄不了」（原生层实现、入口拿不到参数）才研究原理。

**判据**：改完后两个入口的产物应逐字同构（同前缀、同槽位标记 `(云N)`、同 `@import=js:` 尾巴）。不同构 = 没真正复用。

## 排除掉的错误方向

曾计划拆海阔 APK 研究 `sharePaste` / `parsePaste`。方向错了：
星集请求 → 海阔处理 → 成功即可，不需要懂海阔内部；要修的是星集自己调了哪套。
